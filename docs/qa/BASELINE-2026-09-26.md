# RollPhase performance baseline (before any fixes), 2026-09-26

**Build measured:** 0.6.6, buildId `20260924-1309-88d9bc5`.
- Public beta: https://mpdev007.github.io/rollphase-beta/ (GitHub Pages, = master 811929c).
- Local copy: http://127.0.0.1:8880/ (`python -m http.server`), which is master plus the uncommitted "Your Muse" card.

**How it was measured:**
- Lighthouse 12.8.2, default mobile preset, 3 runs per target.
- Playwright 1.62 with real Chrome 154 (headless), set up like the owner's phone: 360x740 at DPR 4, touch, Chrome 154 Android UA, Austin GPS. Tab switches were also run at 390x844 and 412x915.
- CPU throttle through CDP at **4x** (as asked), repeated at **1x** as a cross-check (see caveat C1).
- Every third-party answer was replayed from a local HTTPS fixture server: Nominatim, Photon, Overpass, OSM tiles, unpkg and Google Fonts, each answered in about 1-5 ms. Same-origin files came live from Pages or from localhost.
- 5 runs per metric. Every table shows **median / p90**. p90 is nearest-rank, so with 5 runs it equals the slowest run.

**Paths:** `<AUDIT>` = `_audits/rollphase-qa-2026-09-26 (local evidence archive, not in the repo)`, and evidence is under `<AUDIT>/benchmark/`. Code references are `file:line` in `projects/rollphase/prototype/`. First-pass ids (B/M/N) are from `QA-MAXDEEP-2026-09-25.md`.

- Forced reflow: LH names mobile-shell.js line 46 (0-based in its JSON), which is `onReady` at mobile-shell.js:47-50 (`applyMode` → `setAppHeight` → `vv.height`, then `tab.getBoundingClientRect()`). This is the same forced-layout path as win 4.

**How the Pages-vs-local comparison is skewed:**
- **Pages** is a CDN: HTTP/2, gzip, `max-age=600`, about 45-51 ms server response.
- **`python -m http.server`** has no compression and no cache headers. Its RTT is about 0 ms, but LH's simulated slow-4G applies the same 150 ms RTT and 1.6 Mbps to both. Because the local server sends everything uncompressed, it looks *worse*: LCP 12.3 s vs 9.8 s, and 281 KiB of "unused JS" vs 42 KiB.
- Timing scores are driven by the simulation, so the two differ by only a few points. Byte figures differ a lot. **Quote the beta figures**; the local ones only show what compression hides.

## 6. Caveats: read before quoting a number

- **C1. The 4x CDP throttle distorts timers on this laptop.** Inside the booted app at 4x, a `setTimeout(1100)` fired after 1.6-4.1 s, even though a 6-s trace showed the main thread idle (`sanity-timers-app.json`, `idle-home-4x.json`). A blank page at 4x fired on time, and so did the app at 1x (1.10-1.11 s). The calibration loop showed an effective slowdown of 3-12x instead of 4x.
  - So the 4x venue times (which include the 1.1-s sleeps) are inflated.
  - Use the **1x** rows for anything that involves time to venues.
  - 4x is still a fair stress view of main-thread work: taps, renders, layouts.
- **C2. The host was never idle.** Windows reported 100% machine-wide CPU after every run, from other workloads on the laptop (a Dart VM, Node, git, Gradle and other sessions). Nothing was stopped. The LH benchmarkIndex swung from 914 to 1,686. Expect about ±30% noise on 4x medians and heavy p90 tails; for example, one cold boot at 412 took 39 s.
- **C3. Software compositing.** Headless Chrome here has no GPU, so blur and raster costs are exaggerated compared with a phone GPU. Treat the scroll A/B as relative.
- **C4. Main thread only.** The CPU throttle slows only the main thread. JPEG decode and raster run on other threads, so the picker and image timings understate a slow phone. The 88 MB decoded-bitmap figure is Σ w×h×4, computed, not measured.
- **C5. Replay latency is not a network.** The fixture server answers in about 1-5 ms. Real Nominatim, Photon and Overpass add their own latency on top of the sleep floor in win 1, and Overpass can hang for 14 s per mirror (= M16).
- **C6. The phone.** The owner's S25 is a flagship. For it, the 1x rows are the closer guide (an estimate; no phone was touched). The 4x rows stand for the Moto G class that Lighthouse emulates.
- **C7. The 09-25 S25 walk's `switch_ms` (2.7-2.9 s) is not app time.** `s25_walk.py:116-122` includes a 1.5-s sleep and an adb uiautomator subprocess in that number. Don't cite it as tab-switch latency.
- **C8. Harness hiccups.** 2 of 1,785 replayed answers fell through to the dead kumi mirror; the server answered 502 at once and the app moved on to overpass-api.de. Early smoke runs, kept in `results/smoke/`, replayed through Playwright routes, which added 40-300 ms per request and switched off the HTTP cache. None of the numbers above come from them.

## 7. Traffic to free public APIs

- **Lighthouse:** 0 calls. Location was not granted, so no venue search ran.
- **Playwright:** 12 live requests in total (the cap was 20), listed in `fixtures/live-ledger.jsonl`:
  - 11 OSM tiles at z14, first seen on the direct `#/gyms` path;
  - 1 attempt to overpass.kumi.systems, which timed out with no answer.
- **Everything else:** replayed from the 09-25 recordings, seeded into `fixtures/` and marked in `fixtures/SOURCE.txt`, plus those 12 new ones.
- **Blocked:** formsubmit.co and Google Places are answered with 403 locally. The enrich POST to 127.0.0.1:8877 finds nothing listening.
- **Nothing else was touched:** no phone or adb, and nothing written inside `projects/`.
- **To re-run:** the self-signed certificate for the local replay server was deleted after the runs. Recreate it with `MSYS_NO_PATHCONV=1 openssl req -x509 -newkey rsa:2048 -nodes -keyout pw/tls/key.pem -out pw/tls/cert.pem -days 7 -subj /CN=rollphase-bench-fixtures -addext "subjectAltName=DNS:*.tile.openstreetmap.org,DNS:nominatim.openstreetmap.org,DNS:photon.komoot.io,DNS:lz4.overpass-api.de,DNS:overpass-api.de,DNS:overpass.kumi.systems,DNS:unpkg.com,DNS:fonts.googleapis.com,DNS:fonts.gstatic.com,DNS:formsubmit.co,DNS:places.googleapis.com"`, then start `python pw/fixture_server.py` before any `pw/*.py`. Chrome is launched with `--host-resolver-rules`, which maps the third-party hosts to that server, and with `--disable-features=LocalNetworkAccessChecks,…`. Without the server running, every third-party request fails.
